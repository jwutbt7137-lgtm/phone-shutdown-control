### 5. 端到端自测脚本（结论：本机不可用）

```powershell
python test_e2e.py
```

**实测结论：Windows 不支持本机 BLE 客户端连自己的 GATT 服务。**

```
BluetoothLEDevice.from_bluetooth_address_async(本机地址)  →  返回 None
```

这是操作系统层面的限制，不是服务缺陷。所以这个脚本在本机跑不通，
它真正的用途是：**插一个 USB 蓝牙适配器**，把那个适配器的地址
用 `--address` 传进去，让它当客户端连内置蓝牙上的服务。

## 二、还没验证的（必须靠手机）

| 环节 | 为什么没法在电脑上验 |
| --- | --- |
| 手机能否扫到电脑的广播 | Windows 的 BLE 扫描器扫不到自己发出的广播（系统设计如此） |
| 手机能否连上 GATT 服务 | 同上；本机自连被 `from_bluetooth_address_async` 拒绝 |
| PIN 认证在真机上的表现 | 需要真实客户端 |
| 关机命令真的关掉电脑 | 没敢在验证阶段真关机 |

这些都必须装 App 实测。出问题的排查步骤见 [故障排查.md](故障排查.md)。

## 三、重要修正：广播名在 Windows 上设不了

`--self-test` 里显示「可设置广播名 PC-Shutdown」，那只是在**内存里赋值成功**。
真实启动时 `publisher.start()` 会抛 `参数错误 (0x80070057)`。

逐项实验的结论：

| 尝试 | 结果 |
| --- | --- |
| `advertisement.local_name = "PC-Shutdown"` | ✗ 抛参数错误 |
| `advertisement.service_uuids.append(...)` | ✗ 抛参数错误 |
| `advertisement.manufacturer_data.append(...)` | ✗ Python winrt 绑定报 `convert_to returned null` |
| `advertisement.data_sections.append(自定义段)` | ✓ 可用 |

因此改成用自定义数据段承载标识 `PSD1`（十六进制 `50 53 44 31 01`），
手机端解析到它就认定"这是关机服务"。

**如果你希望手机上显示一个好看的名字**：在
Windows 设置 → 蓝牙和其他设备 → 关于 → 重命名这台电脑，改成一个好认的名字。
